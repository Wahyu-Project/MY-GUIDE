1.AMP Dashboard

Halaman utama AMP Dashboard memberikan ringkasan (overview) data usage CPU, Memory dan Disk secara real-time. Akses AWS CloudWatch dengan link dan akun berikut:

URL
https://cloudwatch.amazonaws.com/
User
helpdesk@tirtanawasena.com
Password
••••••••••••

Fokuskan monitoring pada pergerakan grafik CPU, Memory dan Disk. Pilih Maximize dan setting standar Maximum pada masing-masing server. Fungsi monitoring tiap grafik:

AMP Server CPU

Memantau tren beban prosesor server dari waktu ke waktu. Garis yang melonjak tajam (spike) menandakan proses komputasi berat pada server.

AMP Server Memory

Memantau penggunaan RAM. Garis datar dan konsisten berarti stabil; lonjakan tajam umumnya karena peningkatan trafik atau query data yang masif.

AMP Server Disk

Memantau penggunaan ruang penyimpanan. Kenaikan terus-menerus atau lonjakan mendadak menandakan disk mendekati penuh, misalnya karena log atau file besar.

2.Fitur AMP Dashboard

Team Helpdesk bisa menyesuaikan rentang waktu, detail grafik, zona waktu, hingga pembaruan otomatis tanpa mengubah konfigurasi dari backend.

Interval (Interval Grafik)
Menentukan jarak rentang waktu antar titik data pada grafik (contoh: data dikelompokkan setiap 5 menit).
Standar Option
Menentukan metode kalkulasi atau agregasi angka pada grafik (contoh: nilai rata-rata atau Average).
Time Setting
Menentukan cakupan riwayat data yang ditampilkan: 1 jam terakhir (1h), 1 hari terakhir (1d), hingga rentang khusus lewat opsi Custom.
Time Local
Menentukan acuan zona waktu pada sumbu grafik, mengikuti zona waktu lokal perangkat (Local timezone) atau UTC.
Refresh Interval
Menentukan seberapa sering data dimuat ulang otomatis (contoh: diperbarui setiap 2 menit).

3.Threshold (Ambang Batas)

80%Ambang batas yang disepakati team SIG. Di atas nilai ini, kondisi CPU, Memory atau Disk dianggap kritis.

Jika usage mencapai atau melebihi 80%, lakukan langkah berikut:

  1. Cek status server pada PAM (CyberArk).
  2. Eskalasi ke team Synxchro (Mas Anggi) untuk pengecekan lebih lanjut, lampirkan capture grafik dan status server di CyberArk.
  3. Secara paralel, informasikan ke user/PIC SIG bahwa usage mencapai atau melebihi threshold 80% dan sedang dilakukan pengecekan.
  4. Setelah pengecekan, informasikan Root Cause dan Action atau mitigasi.
  5. Input ke file data log Spike. Jika menyebabkan kendala pada server, masukkan juga ke Incident Report sebagai dokumentasi bila dibutuhkan user.

4.Lost Grafik

Lost grafik bisa disebabkan server down atau restart aplikasi pengumpul metrik (Prometheus) setelah aktivitas housekeeping.

  1. Cek status server pada PAM (CyberArk).
  2. Eskalasi ke team Synxchro (Mas Anggi) untuk pengecekan lebih lanjut, lampirkan capture lost grafik dan status server di CyberArk.
  3. Secara paralel, informasikan ke user/PIC SIG bahwa terdapat lost grafik dan sedang dilakukan pengecekan.
  4. Setelah pengecekan, informasikan Root Cause dan Action atau mitigasi.
  5. Input ke file data Incident Report sebagai dokumentasi bila dibutuhkan user.
