AWS CloudWatch

Tools Monitoring CloudWatch dari Amazon Web Services (AWS) membantu mempermudah dalam proses pemantauan (monitoring) data operasional usage terhadap resouce server AMP secara real-time.


Flow Proses Monitoring

Halaman utama AMP-Dashboard memberikan ringkasan menyeluruh (overview) mengenai data usage CPU, Memory dan Disk secara real-time. Untuk mengakses AWS CloudWatch bisa menggunakan Link dan user akun sebagai berikut :

2. Fiture AMP Dashboard

Fiture AMP Dashboard dibuat untuk mempermudah pemantauan data secara fleksibel dan real-time. Team Helpdesk bisa bebas menyesuaikan rentang waktu, tingkat detail grafik, zona waktu, sampai pembaruan otomatis sesuai kebutuhan analisis tanpa perlu ribet ubah konfigurasi dari backend.

Fiture Aws Fungsi FIture
Interval (Interval Grafik) Menentukan jarak atau pemisahan rentang waktu antar titik data pada grafik (pada contoh : data dikelompokkan setiap 5 menit sekali)
Standar Option Menentukan metode kalkulasi atau agregasi data yang digunakan untuk menampilkan angka pada grafik (pada contoh : menggunakan nilai rata-rata atau Average).
Time Setting Menentukan cakupan rentang waktu riwayat data yang ingin ditampilkan pada dashboard (pilihan mulai dari 1 jam terakhir (1h), 1 hari terakhir (1d), hingga rentang khusus lewat opsi Custom).
Time Local Menentukan acuan zona waktu (timezone) yang dipakai untuk membaca waktu pada sumbu grafik, seperti mengikuti zona waktu lokal perangkat Anda (Local timezone) atau UTC.
Refresh Interval Menentukan seberapa sering sistem memuat ulang (auto-refresh) data di dashboard secara otomatis (pada contoh: data diperbarui setiap 2 menit sekali).

3. Threshold (Ambang Batas)

Dalam prosoes monitoring team Helpdesk perlu memperhatikan threshold (ambang batas) yang telah disepakati oleh team (SIG) yakni 80% yang digunakan sebagai nilai acuan toleransi untuk menentukan apakah kondisi CPU, Memory dan Disk masih dalam kategory normal atau sudah memasuki tahap kritis.

Langkah - langkah yang harus dilakukan bila terdapat usage mencapai atau melebihi threshold 80%, sebagai berikut :

  1. Cek Status Server pada PAM (CyberArk).
  2. Eskalasi ke team Synxchro (Mas Anggi) untuk dilakukan pengecekan lebih lanjut, dengan melampirkan capture grafik dan status server di CyberArk.
  3. Secara Paralel informasikan ke user/PIC dari SIG bahwa terdapat penggunaan mencapai atau melebihi threshold 80% dan sedang dilakukan pengecekan.
  4. Setelah dilakukan pengecekan informasikan Root Cause dan Action atau mitigasi dari hasil pengecekan.
  5. Input ke file data log Spike dan bila menyebabkan kendala pada server masukan ke Incident Report sebagai Dokumentasi bila dibutuhkan User.

4. Lost Grafik

Lost Grafik bisa disebabkan karena Server Down atau adanya restart aplikasi pengumpul metrik (Prometheus) setelah aktifitas houskeping.

  1. Cek Status Server pada PAM (CyberArk).
  2. Eskalasi ke team Synxchro (Mas Anggi) untuk dilakukan pengecekan lebih lanjut, dengan melampirkan capture lost grafik dan status server di CyberArk.
  3. Secara Paralel informasikan ke user/PIC dari SIG bahwa terdapat lost grafik dan sedang dilakukan pengecekan.
  4. Setelah dilakukan pengecekan informasikan Root Cause dan Action atau mitigasi dari hasil pengecekan.
  5. Input ke file data Incident Report sebagai Dokumentasi bila dibutuhkan User.
