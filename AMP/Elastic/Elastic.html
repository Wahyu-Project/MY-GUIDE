Fokus Monitoring pada tools Elastic - Kibana yaitu untuk melihat berapa jumlah total Request Endpoint yang masuk kategori Success, Exception dan Failed pada retensi 60 hari kebelakang untuk data log yang lebih dari 60 hari akan dilakukan housekeeping, dari data endpoint yang memilki log pada tools Elastic - Kibana tersebut bisa dijadikan acuan atau rekomendasi untuk kebutuhan pengecekan dan troubleshooting, berikut ini adalah penjelasan detail terkait Total Request Success, Exception dan Failed.

Success (Res Code 200) Failed (Res Code 400) Exception (Res Code 500)
Analisis Data : Request Success dengan Res Code 200 menandakan Request dari client berhasil diterima, diproses, dan dikembalikan oleh sistem tanpa ada kendala. Analisis Data : Request gagal diproses yang umumnya disebabkan oleh kesalahan di sisi Client dikarenakan beberapa kondisi seperti format request salah, autentikasi gagal (token invalid), atau endpoint tidak ditemukan. Analisis Data : Request gagal karena terjadinya malfungsi pada sistem internal (Server-side error) yang dapat disebabkan karena database connection loss, timeout ke layanan pihak ketiga, atau bug aplikasi.
Action : Tidak ada Action yang perlu dilakukan, jika user masih mengeluhkan kendala, konfirmasikan bahwa sistem berhasil merespons request arahkan pengecekan ke sisi eksternal (koneksi internet user, atau tampilan frontend/UI user). Action : Jika terdapat request Failed dalam jumlah masif, tim Helpdesk wajib melakukan penarikan data dengan mengekspor atau menyalin daftar endpoint pada log detail. Selanjutnya, periksa kolom request body dan response body untuk menganalisis parameter yang dikirimkan oleh user. Hasil analisis tersebut kemudian dilaporkan kepada PIC SIG (Pak Kardo) untuk dikoordinasikan langsung ke pihak user dan informasikan juga ke team synxchro untuk dilakukan pengecekan dari sisi service AMP. Action : Jika terdapat request Exception dalam jumlah masif, tim Helpdesk harus segera menarik data daftar endpoint pada log detail dan mengecek detail error pada kolom request body serta response body. Informasi error yang ditemukan lalu diserahkan kepada PIC SIG (Pak Kardo) agar dapat segera ditindaklanjuti oleh tim terkait dan informasikan juga ke team synxchro untuk dilakukan pengecekan dari sisi service AMP.

Note : untuk detail erorr Failed dan Exception dapat dilihat di kolom Request dan response pada menu detail request Elasticsearch - Kibana.


2. Flow Penarikan Data Log Endpoint

Sehubungan dengan kebutuhan data report weekly dan report monthly team helpdesk dapat melakukan penarikan, mengekspor atau menyalin data log endpoint pada tools Elastic - Kibana berdasarkan periode report, berikut ini adalah langkah - langkah proses penarikan log endpoint terdaftar, log endpoint Exception dan endpoint Failed berdasarkan periode report weekly dan report monthly.

Flow Penarikan data log Endpoint
Cara Penarikan data Log Endpoint Active dan Hight Avarage duration Cara Penarikan data Log Failed & Exception
  1. Modify Waktu sesuai dengan periode yang di inginkan
  2. Klik Option titik 3 pada bagian Total By Endpoint lalu pilih more dan maximize
  3. Setelah data log muncul team helpdesk dapat melihat informasi execution_time_ms dan response_body_length pada masing - masing endpoint
  4. Team helpdesk dapat mendownload/export data pada menu Option titik 3.
  1. Buat Filter request berdasarkan Log request Failed & Exception
  2. Modify Waktu sesuai dengan periode yang di inginkan
  3. Klik Option titik 3 pada bagian Detail Request lalu pilih more dan maximize
  4. Setelah data log team helpdesk dapat melihat informasi log error secara detail pada masing - masing endpoint
  5. Team helpdesk dapat mendownload/export data pada menu Option titik 3.

Note : Log Endpoint Active berdasarka Tier 1 - Log 2 Minggu (0-14 hari), Tier 2 - Log 30 Hari (15 - 30 hari), dan Tier 3 - Log 60 Hari (31 hari - 60 hari).
