Tools Grafana

Tools Grafana membantu mempermudah dalam proses pemantauan (monitoring) data operasional usage terhadap resouce server AMP secara real-time.


Flow Proses Monitoring

1. Grafana Dashboard

Halaman utama Grafana-Dashboard memberikan ringkasan menyeluruh (overview) mengenai data usage CPU, Memory dan Disk secara real-time. Untuk mengakses Grafana team helpdesk bisa menggunakan Link dan user akun sebagai berikut :

  • URL : https://grafana.sig.id/

Fokus Monitoring pada pergerakan grafik CPU, MEMORY dan DISK pada halaman Grafana-Dashboard pastikan pada fiture JOB pilih aws-linux, Host pilih Server AMP yang diinginkan.

Berikut ini adalah fungsi monitoring AMP Server CPU, MEMORY dan DISK :

  1. AMP Server - CPU

    2. Memantau tren beban prosesor server dari waktu ke waktu. Jika ada garis yang melonjak tajam (spike), itu menandakan adanya proses komputasi yang berat pada server.

  2. AMP Server - Memory

    3. Memantau penggunaan RAM. Garis yang datar dan konsisten menandakan penggunaan memory yang stabil, sebaliknya jika terdapat lonjakan tajam (spike), hal tersebut umumnya disebabkan oleh peningkatan trafik atau query data yang masif.

  3. AMP Server - Disk

    4. Memantau penggunaan Disk. Garis yang datar dan konsisten menandakan penggunaan memory yang stabil, sebaliknya jika terdapat lonjakan tajam (spike), menandakan terdapat proses tulis/baca yang intensif seperti backup, migrasi file besar, atau query basis data yang berat.

2. Fiture Grafana-Dashboard

Fiture Grafana-Dashboard dibuat untuk mempermudah pemantauan data secara fleksibel dan real-time. Team Helpdesk bisa bebas menyesuaikan rentang waktu, tingkat detail grafik, sampai pembaruan otomatis sesuai kebutuhan analisis tanpa perlu ribet ubah konfigurasi dari backend.

  1. Fiture JOB

    2. Sebagai filter variabel dinamis untuk menyaring dan mengelompokkan data metrik berdasarkan layanan server

  2. Interval (Interval Grafik)

    3. Menentukan jarak atau pemisahan rentang waktu antar titik data pada grafik (pada contoh : data dikelompokkan setiap 5 menit sekali).

  3. Host

    4. Team Helpdesk dapat memilih server yang ingin di tampilkan informasi detail tren pergerakan grafik penggunaan dab resouce pada sistem monitoring grafana.

  4. instance

    5. Team Helpdesk dapat memilih IP Addres beserta port server secara spesifik.

  5. Time Setting

    6. Menentukan cakupan rentang waktu riwayat data yang ingin ditampilkan pada dashboard (pilihan mulai dari 1 jam terakhir (1h), 1 hari terakhir (1d), hingga rentang khusus lewat opsi Custom).

  6. Refresh Interval

    7. Menentukan seberapa sering sistem memuat ulang (auto-refresh) data di dashboard secara otomatis (pada contoh: data diperbarui setiap 1 menit sekali).

3. Threshold (Ambang Batas)

Dalam prosoes monitoring team Helpdesk perlu memperhatikan threshold (ambang batas) yang telah disepakati oleh team (SIG) yakni 90% yang digunakan sebagai nilai acuan toleransi untuk menentukan apakah kondisi CPU, Memory dan Disk masih dalam kategory normal atau sudah memasuki tahap kritis.

Langkah - langkah yang harus dilakukan bila terdapat usage mencapai atau melebihi threshold 90%, sebagai berikut :

  1. Cek Status Server pada PAM (CyberArk).
  2. Eskalasi ke team Synxchro (Mas Adam) untuk dilakukan pengecekan lebih lanjut, dengan melampirkan capture grafik dan status server di CyberArk.
  3. Secara Paralel informasikan ke user/PIC dari SIG bahwa terdapat penggunaan mencapai atau melebihi threshold 90% dan sedang dilakukan pengecekan.
  4. Setelah dilakukan pengecekan informasikan Root Cause dan Action atau mitigasi dari hasil pengecekan.
  5. Input ke file data log Spike dan bila menyebabkan kendala pada server masukan ke Incident Report sebagai Dokumentasi bila dibutuhkan User.

4. Lost Grafik

Lost Grafik bisa disebabkan karena Server Down atau adanya restart aplikasi pengumpul metrik (Prometheus) setelah aktifitas houskeping.

  1. Cek Status Server pada PAM (CyberArk).
  2. Eskalasi ke team Synxchro (Mas Adam) untuk dilakukan pengecekan lebih lanjut, dengan melampirkan capture lost grafik dan status server di CyberArk.
  3. Secara Paralel informasikan ke user/PIC dari SIG bahwa terdapat lost grafik dan sedang dilakukan pengecekan.
  4. Setelah dilakukan pengecekan informasikan Root Cause dan Action atau mitigasi dari hasil pengecekan.
  5. Input ke file data Incident Report sebagai Dokumentasi bila dibutuhkan User.
