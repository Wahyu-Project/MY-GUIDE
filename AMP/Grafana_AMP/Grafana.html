Tools Grafana

Tools Grafana membantu mempermudah dalam proses pemantauan (monitoring) data operasional usage terhadap resource server AMP secara real-time.

  • Grafana Dashboard
  • Fitur Grafana
  • Threshold 80%
  • Lost Grafik

1.Grafana Dashboard

Halaman utama Grafana-Dashboard memberikan ringkasan menyeluruh (overview) mengenai data usage CPU, Memory dan Disk secara real-time. Akses Grafana dengan link berikut:

URL
https://grafana.sig.id/

Fokus monitoring pada pergerakan grafik CPU, MEMORY dan DISK. Pastikan pada fitur JOB pilih aws-linux, dan Host pilih Server AMP yang diinginkan. Berikut adalah fungsi monitoring tiap grafik:

AMP Server CPU

Memantau tren beban prosesor server dari waktu ke waktu. Jika ada garis yang melonjak tajam (spike), itu menandakan adanya proses komputasi yang berat pada server.

AMP Server Memory

Memantau penggunaan RAM. Garis datar berarti stabil, sebaliknya lonjakan tajam (spike) umumnya disebabkan oleh peningkatan trafik atau query data yang masif.

AMP Server Disk

Memantau penggunaan ruang penyimpanan. Lonjakan tajam (spike) menandakan terdapat proses tulis/baca yang intensif seperti backup, migrasi file besar, atau query basis data yang berat.

2.Fitur Grafana-Dashboard

Dibuat untuk mempermudah pemantauan data secara fleksibel. Team Helpdesk bisa bebas menyesuaikan rentang waktu hingga tingkat detail grafik tanpa perlu merubah konfigurasi backend.

Job
Sebagai filter variabel dinamis untuk menyaring dan mengelompokkan data metrik berdasarkan layanan server.
Interval (Grafik)
Menentukan jarak atau pemisahan rentang waktu antar titik data pada grafik (contoh: data dikelompokkan setiap 5 menit sekali).
Host
Team Helpdesk dapat memilih server yang ingin ditampilkan informasi detail tren pergerakan grafik penggunaannya.
Instance
Team Helpdesk dapat memilih IP Address beserta port server secara spesifik.
Time Setting
Menentukan cakupan rentang waktu riwayat data yang ingin ditampilkan (mulai dari 1 jam terakhir (1h), 1 hari (1d), hingga Custom).
Refresh Interval
Menentukan seberapa sering sistem memuat ulang (auto-refresh) data di dashboard secara otomatis (contoh: diperbarui setiap 1 menit).

3.Threshold (Ambang Batas)

80%Ambang batas yang disepakati team SIG. Digunakan sebagai acuan apakah kondisi CPU, Memory, atau Disk masih normal atau kritis.

Langkah-langkah yang harus dilakukan bila usage mencapai atau melebihi threshold 80%:

  1. Cek Status Server pada PAM (CyberArk).
  2. Eskalasi ke team Synxchro (Mas Anggi) untuk pengecekan lebih lanjut, lampirkan capture grafik dan status server di CyberArk.
  3. Secara paralel informasikan ke user/PIC dari SIG bahwa terdapat penggunaan mencapai/melebihi threshold 80% dan sedang dilakukan pengecekan.
  4. Setelah pengecekan, informasikan Root Cause dan Action atau mitigasi dari hasil pengecekan.
  5. Input ke file data log Spike. Bila menyebabkan kendala pada server, masukan ke Incident Report sebagai dokumentasi bila dibutuhkan User.

4.Lost Grafik

Lost Grafik bisa disebabkan karena Server Down atau adanya restart aplikasi pengumpul metrik (Prometheus) setelah aktifitas housekeeping.

  1. Cek Status Server pada PAM (CyberArk).
  2. Eskalasi ke team Synxchro (Mas Adam) untuk pengecekan lebih lanjut, lampirkan capture lost grafik dan status server di CyberArk.
  3. Secara paralel informasikan ke user/PIC dari SIG bahwa terdapat lost grafik dan sedang dilakukan pengecekan.
  4. Setelah pengecekan, informasikan Root Cause dan Action atau mitigasi dari hasil pengecekan.
  5. Input ke file data Incident Report sebagai dokumentasi bila dibutuhkan User.
